\subsection{Data Flow of One Solve}
\label{sec:data_flow}

\begin{lstlisting}[language=Python]
solve(input_path, results_path="output.yaml", *,
      warm_start=None, warm_start_mode="start") -> dict
\end{lstlisting}
\begin{enumerate}[nosep,label=\arabic*.]
  \item Check the input file: it exists (\texttt{FileNotFoundError}) and has the extension \texttt{.yaml}, \texttt{.yml}, \texttt{.json}, \texttt{.h5} or \texttt{.hdf5} (\texttt{ValueError}). Check \texttt{results\_path} (Section~\ref{sec:output_files}).
  \item Read the file with the input reader (Section~\ref{sec:schema}) into a mapping. If the data of the file are not a mapping, the reader raises \texttt{TypeError}.
  \item \texttt{load\_config}: normalise the mapping into a \texttt{FleetConfig} and run the checks of Section~\ref{sec:consistency_checks} (\texttt{ValueError}).
  \item Build the model (Section~\ref{sec:builders}), apply the warm start (Section~\ref{sec:warm_starts}) and optimise.
  \item Extract the result (Section~\ref{sec:output}): the shared extraction, then the \texttt{extract} hook of each builder. Write the result file (Section~\ref{sec:output_files}) and return the result.
\end{enumerate}
Steps 3 to 5 form the internal entry point \texttt{solve\_mapping(data, results\_path=None, *, warm\_start=None, warm\_start\_mode="start")}, which takes the mapping of step~2. It first checks \texttt{warm\_start\_mode} (\texttt{ValueError} for a value other than \texttt{"start"}, \texttt{"hint"} and \texttt{"both"}), then \texttt{results\_path}. So \texttt{solve} reports an unreadable input file, or data that are not a mapping, before a wrong \texttt{warm\_start\_mode}. \texttt{load\_config} raises \texttt{TypeError} for data that are not a mapping, which matters for a direct call of \texttt{solve\_mapping}. Gurobi errors are not caught, except those of the warm-start completion and of the relaxation start (Section~\ref{sec:warm_starts}).

\subsection{Cell-Builder Interface}
\label{sec:builders}

A registry maps each model name (\texttt{gaussian}, \texttt{inverse\_gaussian}, \texttt{wiener}, \texttt{gamma}, \texttt{rainflow}) to a builder; the model of cell $(i,\ell)$ is its entry of \texttt{model}.
\begin{lstlisting}[language=Python]
register_cell_builder(name, builder)  # CELL_BUILDERS[name] = builder
get_cell_builder(name)    # NotImplementedError, with the names, if absent
dispatch_cell(ctx, i, l)  # get_cell_builder(ctx.model_of[i, l])
                          #     .add_cell(ctx, i, l)
\end{lstlisting}
A builder has the attribute \texttt{name} and three hooks:
\begin{itemize}[nosep]
  \item \texttt{prepare(ctx, cfg, cells, opts)}: called once per model in the fleet, with its cells. It stores the per-cell arrays of the model in \texttt{ctx}, creates, for these cells only, the variables of the tracked quantities other than the shared mean $\mu$; the anchors; the start of the repetition $y^s$ of every tracked quantity $s$ (also $\mu$) and $y^{g,s}$ of every anchor (Section~\ref{sec:loop}); the selectors $n$ (cells with \texttt{encoding = indicator}); and the segment binaries $w$ (quadratic rows in the form \texttt{pwl}). It may tighten variable bounds, and sets Gurobi's \texttt{NonConvex} to $2$ if some cell keeps an exact quadratic row.
  \item \texttt{add\_cell(ctx, i, l)}: adds the rows of one cell (Section~\ref{sec:constraints}): dynamics in the form of \texttt{encoding}, replacement and anchor rows, the start rows and the loop rows of the full tracked state (built with the dynamics, see below), reliability rows in the form of \texttt{reliability\_impl}, repair-cost rows.
  \item \texttt{extract(ctx, cfg, out)}, optional: adds model-specific entries to the result \texttt{out} after the shared entries.
\end{itemize}
\blockhead{Members of the context \texttt{ctx}}
\tabstart{p{4.6cm}p{10.4cm}}{Member & Content}
\rejrow{\texttt{F}, \texttt{L}, \texttt{M}, \texttt{H1}, \texttt{H2}, \texttt{T}}{the sizes}
\rejrow{\texttt{model}}{the Gurobi model}
\rejrow{\texttt{x}, \texttt{m\_rep}, \texttt{r\_rep}, \texttt{mu\_var}, \texttt{z\_var}, \texttt{u\_var}}{the shared variables $x$, $x^m$, $x^r$ (\texttt{None} if replacement is not allowed), $\mu$, $z$ (cells with $C_R > 0$, on the days whose cost enters the objective) and $u$ (\texttt{None} if $C_D = 0$), with the shapes of Section~\ref{sec:variables}}
\rejrow{\texttt{model\_of}, \texttt{repair\_of}, \texttt{bound\_of}, \texttt{impl\_of}, \texttt{encoding\_of}}{the selectors of each cell, arrays $F \times L$ of text}
\rejrow{\texttt{tau}, \texttt{eps}, \texttt{rho}, \texttt{tangent\_ref}}{arrays $F \times L$ of floats}
\rejrow{\texttt{initial}, \texttt{replacement}, \texttt{anchor\_start}, \texttt{state\_range}}{dictionaries from the quantity name (\texttt{"mu"}, \texttt{"v"}, \texttt{"R"}, \texttt{"K"}) to an array $F \times L$: initial value, replacement value, starting anchor, natural range}
\rejrow{\texttt{allow\_replacement}, \texttt{pwl\_points}, \texttt{opts}, \texttt{profiles}}{the options \texttt{allow\_replacement} and \texttt{pwl\_points}; the run options; the increment profiles, from the key (\texttt{"mu"}, \texttt{"v"}, \texttt{"support"}, \texttt{"cgf"}, \texttt{"gamma\_beta"}) to the pair (operating, transitory or \texttt{None})}
\rejrow{\texttt{state\_vars}, \texttt{anchor\_vars}}{from the quantity name to the variables by $(i, \ell, k)$; \texttt{state\_vars["mu"]} is \texttt{mu\_var}; the anchors exist at \texttt{ard1} cells}
\rejrow{\texttt{start\_vars}, \texttt{start\_anchor\_vars}}{from the quantity name to the variables $y^s$ and $y^{g,s}$ by $(i, \ell)$}
\rejrow{\texttt{nb}, \texttt{pwl\_w}}{the selectors $n$ by $(i, \ell, k)$ and the segment binaries $w$ by $(i, \ell, k, p)$}
\rejrow{\texttt{extras}}{a dictionary from the name of a builder to its own data (next table)}
\tabend
The increment accessor \texttt{ctx.increment(key, i, j, l, k)} returns the increment after the phase lookup, Eq.~\eqref{eq:c_phase}, with $j = 0$ the depot (increment $0$).

\blockhead{Entries of \texttt{ctx.extras}}
\tabstart{p{4.0cm}p{11.0cm}}{Key and entry & Content}
\rejrow{\texttt{"gaussian"}: \texttt{v\_max\_user}}{array $F \times L$; \texttt{NaN} where the input gives no bound}
\rejrow{\texttt{"wiener"}: \texttt{sigma}, \texttt{v\_max\_user}}{arrays $F \times L$}
\rejrow{\texttt{"inverse\_gaussian"}: \texttt{mu\_bar}}{the cap $\bar\mu$ of each cell, by $(i, \ell)$}
\rejrow{\texttt{"gamma"}: \texttt{beta\_star}, \texttt{cap}}{$\beta^\ast$ and the cap of each cell, by $(i, \ell)$}
\rejrow{\texttt{"rainflow"}: \texttt{rows}}{by $(i, \ell)$ a mapping of the row constants: the tracked quantity \texttt{q}; \texttt{c2}, \texttt{c1}, \texttt{mu\_side} (quadratic row) or \texttt{cap}; \texttt{v\_max\_user}}
\tabend

\blockhead{Helper functions of \texttt{base.py}}
A builder builds its rows with these helpers. \texttt{prepare} calls:
\begin{itemize}[nosep,leftmargin=1.5em]
  \item \texttt{add\_state\_vars(ctx, q, cells, anchored=True)}: the state of $q$ (not for $\mu$), its anchor at \texttt{ard1} cells (none with \texttt{anchored=False}, as for the Wiener variance), and $y^q$ with $y^{g,q}$; all in the natural range of $q$;
  \item \texttt{add\_selector\_vars(ctx, cells)}: the selectors $n$;
  \item \texttt{add\_pwl\_vars(ctx, cells)}: the segment binaries $w$ (none for \texttt{pwl\_points} $< 2$).
\end{itemize}
\texttt{add\_cell} calls, in this order:
\begin{enumerate}[nosep,label=\arabic*.]
  \item \texttt{add\_selector\_rows}: $n + x^m + x^r = 1$ at an indicator cell (Section~\ref{sec:encoding}).
  \item \texttt{add\_quantity\_rows} (arguments \texttt{ctx}, $i$, $\ell$, $q$, \texttt{increments}, and the option \texttt{repair\_keeps\_state}, default false), once per tracked quantity, $\mu$ first. For one quantity it builds the start rows, then the rows of every day (dynamics in the encoding of the cell, replacement rows, anchor rows; the rows of day $H_1 + 1$ read $y$), then the loop rows. \texttt{increments[k]} is the increment of day index $k$. \texttt{repair\_keeps\_state} is set for the Wiener variance.
  \item The reliability rows: \texttt{add\_upper\_cap\_rows} ($s \le$ cap on every day) or \texttt{add\_quadratic\_reliability\_rows} (reliability row and side row, in the form of the cell), and, where it applies, the optional row $v \le V^{\mathrm{user}}_{\max}$.
  \item \texttt{add\_repair\_cost\_rows}: the rows of $z$.
\end{enumerate}
The reading helpers are \texttt{mission\_count} (arguments \texttt{ctx}, $i$, $k$), \texttt{day\_increment} (arguments \texttt{ctx}, $i$, $\ell$, $k$, \texttt{key}, and the option \texttt{squared}, default false) and \texttt{repair\_factor} (arguments $q$, $\rho$). The fleet rows and the objective are built by \texttt{add\_assignment\_rows}, \texttt{add\_depot\_rows}, \texttt{add\_damage\_penalty\_rows} and \texttt{build\_objective}.

\blockhead{Errors of the builders}
\tabstart{p{4.2cm}p{10.8cm}}{Exception & Raised when}
\rejrow{\texttt{ValueError}}{a helper reads a value that is not finite: a natural range, an initial value, a starting anchor, a replacement value, \texttt{tangent\_ref} or an increment (the message names the cell; for an increment also the mission and the day); the rainflow \texttt{prepare} reads a support constant or $s_{\mathrm{Chernoff}}$ that is not finite; a variable that \texttt{prepare} should have created is missing; \texttt{increments} does not have $T$ entries; the \texttt{reliability\_impl}, the \texttt{bound\_method} or the tracked quantity is unknown}
\rejrow{\texttt{NotImplementedError}}{a model name has no registered builder (the message lists the names that have one); raised before any Gurobi object exists}
\tabend

\blockhead{Building order}
\begin{enumerate}[nosep,label=\arabic*.]
  \item Create the model, apply the run options, create the shared variables.
  \item Call \texttt{prepare} for each model present, in alphabetical order of the names.
  \item Apply the entries of \texttt{gurobi\_params} again (Section~\ref{sec:run_options}). A \texttt{NonConvex} entry of the user thus wins over the value $2$ that \texttt{prepare} sets.
  \item Build the objective (Section~\ref{sec:objective}) and the rows that do not depend on the model: assignment (Section~\ref{sec:assignment}), depot day (Section~\ref{sec:depot}), damage penalty (Section~\ref{sec:damage_reg}).
  \item Call \texttt{add\_cell} for every cell, $i$ outer, $\ell$ inner.
\end{enumerate}
Each builder defines $\mu_{i\ell k}$, $k = 1,\ldots,T$, for its cells. A model is added by a module with its builder, its registration, its input checks in \texttt{config.py} (Section~\ref{sec:consistency_checks}) and its section in this specification.

\section{Horizon Sweeps}
\label{sec:sweeps}
% ================================================================

A horizon sweep solves one input for several pairs $(H_1, H_2)$ and ranks the cases. \texttt{sweep\_operating\_horizons} varies $H_2$ for one $H_1$; \texttt{sweep\_horizon\_grid} varies $H_1$ and $H_2$.
No input key starts a sweep, and \texttt{solve()} never runs one.

\subsection{Cost Measures and Ranking}
\label{sec:sweep_criteria}

$J_{\mathrm{init}}$ and $J_{\mathrm{op}}$ of a case are Eq.~\eqref{eq:a_phases} on its solution. The cost per operating day, and the projected cost over an evaluation horizon $E > H_1$, are
\begin{equation}
  \bar J_{\mathrm{op}} = J_{\mathrm{op}} / H_2, \qquad
  P_E = J_{\mathrm{init}} + (E - H_1)\,\bar J_{\mathrm{op}} .
  \label{eq:d_projected}
\end{equation}
\begin{itemize}[nosep,leftmargin=1.5em]
  \item \textbf{Feasible case}: its row has an \texttt{objective} that is not \texttt{null}, and its status is not \texttt{"infeasible"}, \texttt{"unbounded"} or \texttt{"inf\_or\_unbounded"}. An error row is not feasible. This test is made on the row. The test for a warm-start source is a different one (Section~\ref{sec:warm_sweeps}).
  \item \textbf{Proven case}: it is feasible and its status is \texttt{"optimal"} at the MIP gap used for the case. This gap is Gurobi's \texttt{MIPGap} after all options are set, \texttt{gurobi\_params} included (Section~\ref{sec:run_options}). It is the entry \texttt{requested\_mip\_gap} of \texttt{performance}.
  \item \textbf{Ranking value}: $\bar J_{\mathrm{op}}$ in \texttt{sweep\_operating\_horizons}. In \texttt{sweep\_horizon\_grid} it is $P_E$ if an evaluation horizon is given, otherwise $\bar J_{\mathrm{op}}$.
  \item \textbf{Best proven case}: the proven case with the smallest ranking value.
  \item \textbf{Best feasible case}: the feasible case with the smallest ranking value.
  \item \textbf{Tie rule}: a tie goes to the smaller $H_2$; in the grid, to the smaller $H_1$, then the smaller $H_2$.
\end{itemize}

\subsection{\texttt{sweep\_operating\_horizons}}
\label{sec:sweep_operating}

Solves one input for several values of $H_2$ with $H_1$ fixed, and ranks the cases.

\end{lstlisting}

The ranking uses $\bar J_{\mathrm{op}}$ in all three modes (Section~\ref{sec:sweep_texts})}
\typerow{\texttt{evaluation\_horizon}}{\texttt{None}}{Written into every case input; if given, an integer $E > H_1$; \texttt{"evaluation\_total"} needs it}
\tabend

\blockhead{Steps}
\begin{enumerate}[nosep,label=\arabic*.]
  \item Read the input file with the input reader (Section~\ref{sec:schema}). The data must be a mapping. Read $H_1$ from \texttt{H}; $H_1 < 1$ is an error.
  \item Check every argument.
  \item For each $H_2$, the case input is the input data with \texttt{H} $= [H_1, H_2]$, and with \texttt{objective\_mode} and \texttt{evaluation\_horizon} (if given) replaced. Time-indexed data are not interpolated: a profile whose length is not $H_2$ fails the checks of Section~\ref{sec:consistency_checks}, as an error of that case.
  \item Solve the case input with \texttt{solve\_mapping} (Section~\ref{sec:data_flow}) and \texttt{results\_path=None}; no temporary file is written. Keep the row of the case, not its schedule.
  \item After each case: append its row, annotate the gradient (Section~\ref{sec:sweep_stop}), test the stop rule, write a checkpoint if \texttt{output\_path} is given.
  \item At the end, write the final report and return it.
\end{enumerate}

Such an error is never recorded as a case error}
\rejrow{none (captured)}{an error inside a case; it is captured in the row of the case (Section~\ref{sec:sweep_report})}
\tabend

\subsection{Early Stop}
\label{sec:sweep_stop}

Let $\bar J_n$ be the cost per operating day of the $n$-th evaluated case. If cases $n-1$ and $n$ are feasible, the relative gradient is
\begin{equation}
  \hat g_n = \frac{\bar J_n - \bar J_{n-1}}{(H_{2,n} - H_{2,n-1})\,\max\{\,|\bar J_{n-1}|,\ \varepsilon_{\mathrm{mach}}\}},
  \label{eq:d_gradient}
\end{equation}
with $\varepsilon_{\mathrm{mach}}$ the machine precision of double-precision numbers. The absolute gradient is $(\bar J_n - \bar J_{n-1})/(H_{2,n} - H_{2,n-1})$ (key \texttt{cost\_gradient\_per\_H2}); it is \texttt{null} where $\hat g_n$ is not available.

\blockhead{Class of a case}
With $t = \texttt{gradient\_tolerance}$, the class of case $n$ is:
\tabstart{p{3.4cm}p{11.6cm}}{Class & Condition}
\rejrow{\texttt{"increase"}}{$\hat g_n > t$}
\rejrow{\texttt{"decrease"}}{$\hat g_n < -t$}
\rejrow{\texttt{"flat"}}{otherwise: $-t \le \hat g_n \le t$}
\rejrow{\texttt{"unavailable"}}{$n = 1$, or one of the two cases is not feasible}
\tabend

\blockhead{Definitions}
\begin{itemize}[nosep,leftmargin=1.5em]
  \item \textbf{Qualifies}: a case qualifies if it reports a finite MIP gap at most its threshold. The threshold is \texttt{maximum\_mip\_gap\_for\_stopping} if it is a number, otherwise the MIP gap used for the case (\texttt{requested\_mip\_gap} of its row).
  \item \textbf{Eligible to stop}: the gradient of case $n$ is eligible to stop if it is available (cases $n-1$ and $n$ are feasible) and cases $n-1$ and $n$ qualify.
  \item \textbf{Annotation}: every row carries its gradient, class and eligibility, also if \texttt{stop\_on\_gradient} is false. An error row carries them too, with class \texttt{"unavailable"}, eligibility \texttt{false} and \texttt{null} gradients.
\end{itemize}

\blockhead{Stop rule}
With \texttt{stop\_on\_gradient=True} the sweep stops after case $n$ if all of these hold:
\begin{enumerate}[nosep,label=\arabic*.]
  \item $n \ge \texttt{minimum\_cases}$.
  \item The gradient of case $n$ is eligible to stop.
  \item One of the two reasons holds:
    \begin{itemize}[nosep]
      \item reason \texttt{"cost\_increase"}: the class of case $n$ is \texttt{"increase"};
      \item reason \texttt{"flat\_gradient"}: the last \texttt{flat\_gradients\_required} cases up to $n$ all have the class \texttt{"flat"} and an eligible gradient.
    \end{itemize}
\end{enumerate}
The last candidate of \texttt{operating\_horizons} is a hard limit. If the rule fires after the last candidate, the sweep records the reason of the rule (\texttt{"cost\_increase"} or \texttt{"flat\_gradient"}), and \texttt{stopped\_early} is \texttt{false}, because no planned case is left out.

\subsection{Report, Checkpoint and Errors}
\label{sec:sweep_report}

The report is a mapping of plain Python types, written as YAML.

\rejrow{\texttt{complete}}{\texttt{false} in a checkpoint}

\rejrow{\texttt{varied\_parameter}}{\texttt{"H2"}}
\rejrow{\texttt{fixed\_dimensions}}{$F$, $M$, $L$ of the input; all three are \texttt{null} if one of them cannot be read}

\rejrow{\texttt{planned\_operating\_horizons}, \texttt{evaluated\_operating\_horizons}}{the planned and the evaluated values of $H_2$}

\rejrow{\texttt{n\_workers}}{number of workers, an integer $\ge 1$}

\subsection{Parallel Cases}
\label{sec:sweep_parallel}

\begin{itemize}[nosep,leftmargin=1.5em]
  \item With $\texttt{n\_workers} > 1$, up to \texttt{n\_workers} cases are solved at the same time, each in a worker process with its own Gurobi environment and one Gurobi licence token.
  \item \textbf{Worker pool}: one pool of \texttt{n\_workers} processes, started with the method \texttt{spawn}. All cases are submitted at once, in increasing order of $H_2$; each worker takes the next case when it is free.
  \item \textbf{Dead worker}: if a worker process dies, every case that has not finished becomes a case error (Section~\ref{sec:sweep_report}), with the message of the pool.
  \item The option is refused with \texttt{warm\_start} and with \texttt{stop\_on\_gradient}.
  \item Rows arrive in the order of completion. The report orders them by $H_2$, and each rewrite recomputes the gradient annotations over the ordered rows.
\end{itemize}

\subsection{Interface and Reports}
\label{sec:warm_interface}
\label{sec:warm_reports}

\begin{itemize}[nosep,leftmargin=1.5em]
  \item \textbf{\texttt{warm\_start}}: an argument of \texttt{solve()}; a source or \texttt{None} (default).
  \item \textbf{\texttt{warm\_start\_mode}}: an argument of \texttt{solve()}; \texttt{"start"} (default), \texttt{"hint"} or \texttt{"both"}. Another value raises \texttt{ValueError}; \texttt{solve\_mapping} checks it first (Section~\ref{sec:data_flow}), and the sweeps check it with their arguments.
  \item \textbf{Source}: a result dictionary or the dictionary returned by the greedy heuristic (Section~\ref{sec:greedy}).
  \item \textbf{Keys of a source}: it carries \texttt{x} (shape $F' \times (M'+1) \times T'$) and the integers \texttt{H1}, \texttt{H2} with $T' = H_1' + H_2'$. It may carry \texttt{m} and \texttt{r} (shape $F' \times L' \times T'$).
  \item \textbf{Source without \texttt{x}}: a source whose \texttt{x} is missing or \texttt{null} has no effect.
  \item \textbf{Invalid source}: \texttt{solve()} raises \texttt{ValueError} for a source with \texttt{x} whose \texttt{H1} or \texttt{H2} is not an integer $\ge 1$ (a number with zero fractional part is one, a flag is not), or whose \texttt{x}, \texttt{m} or \texttt{r} does not have three axes with $T'$ days on the last, or that carries \texttt{completion\_time\_limit} with a value that is not a finite number $\ge 0$ (\texttt{null} and a flag are not). The checks run in this order: \texttt{H1} and \texttt{H2}, \texttt{completion\_time\_limit}, the shapes.
  \item \textbf{Other dimensions}: $F'$, $M'$, $L'$ may differ from $F$, $M$, $L$. Values are set for the indices that both have.
  \item \textbf{Reports}: the result keys \texttt{warm\_start} and \texttt{relaxation\_warm\_start} report what each mechanism did (Section~\ref{sec:output_reports}).
  \item \textbf{Report of a step that did not run}: the entries are those of the table below.
  \item \textbf{Time}: \texttt{model\_construction\_seconds} of \texttt{performance} covers the building of the model and all warm-start phases (mapping, completion, relaxation start), not the optimisation.
\end{itemize}
\tabstart{p{4.6cm}p{10.4cm}}{Step that did not run & Report}
\rejrow{No source, or a source without \texttt{x}}{\texttt{warm\_start}: \texttt{applied} false, \texttt{values} $0$, \texttt{mode} and \texttt{source\_horizon} \texttt{null}; \texttt{completion}: \texttt{requested} the flag of the source (false without a source), \texttt{status} \texttt{"not\_requested"}, \texttt{fixed\_integer\_variables} $0$, \texttt{values\_copied} $0$, \texttt{runtime\_seconds} \texttt{null}, \texttt{iis\_constraints} empty}
\rejrow{Completion not run (mode \texttt{"hint"}, no request, or no value set)}{the \texttt{completion} entries above}
\rejrow{Relaxation start, option false}{\texttt{enabled} false, \texttt{status} \texttt{"disabled"}, \texttt{relaxation\_objective} \texttt{null}, \texttt{values\_copied} $0$, \texttt{runtime\_seconds} \texttt{null}}
\rejrow{Relaxation start, skipped}{as above, with \texttt{enabled} true and \texttt{status} \texttt{"skipped"}}
\tabend

\subsection{Day Mapping}
\label{sec:warm_map}

Day $k \in \{1,\ldots,T\}$ takes the values of the source day
\begin{equation}
  \sigma(k) =
  \begin{cases}
    k, & k \leq \min\{H_1, H_1'\}, \\
    H_1' + 1 + \bigl(\max\{0,\ k - H_1 - 1\} \bmod H_2'\bigr), & \text{otherwise.}
  \end{cases}
  \label{eq:d_daymap}
\end{equation}
The mapped values, rounded to the nearest integer (a tie goes to the even integer; the values are not clipped to $\{0,1\}$), are:
\tabstart{p{4.4cm}p{10.6cm}}{Variable & Value from the source}
\rejrow{$x_{ijk}$ for $j = 0,\ldots,M$}{$x'_{ij\sigma(k)}$}
\rejrow{$x^m_{i\ell k}$}{$m'_{i\ell\sigma(k)}$, or $0$ if the source has no \texttt{m}}
\rejrow{$x^r_{i\ell k}$}{$r'_{i\ell\sigma(k)}$, if \texttt{allow\_replacement} is true and the source has \texttt{r}}
\tabend
A binary variable that these values fix through its defining rows (the selector $n_{i\ell k}$ of Eq.~\eqref{eq:a_ind_sum}) gets that value.

\subsection{Start, Hints and Completion}
\label{sec:warm_start_modes}

\tabstart{p{3.4cm}p{11.6cm}}{Mode & Effect}
\rejrow{\texttt{"start"}}{sets \texttt{Start} of every mapped variable; continuous variables get no value. The completion runs if the source requests it}
\rejrow{\texttt{"hint"}}{sets \texttt{VarHintVal} instead, with no \texttt{Start}, no completion and no \texttt{VarHintPri}}
\rejrow{\texttt{"both"}}{sets \texttt{Start} and \texttt{VarHintVal}. The completion runs if the source requests it}
\tabend

\blockhead{Completion}
\begin{itemize}[nosep,leftmargin=1.5em]
  \item \textbf{Request}: only the source requests it, with \texttt{complete\_binary\_start = true}; the greedy heuristic does.
  \item \textbf{Condition}: it runs if the mapping set at least one value.
  \item \textbf{Time limit}: \texttt{completion\_time\_limit} of the source: a finite number $\ge 0$ (seconds, default $60$); any other value raises \texttt{ValueError} (Section~\ref{sec:warm_interface}).
  \item \textbf{Report}: \texttt{requested} is the flag of the source; while the completion does not run, its status is \texttt{"not\_requested"}.
\end{itemize}
\begin{enumerate}[nosep,label=\arabic*.]
  \item Copy the model; fix every binary and every integer variable that has a \texttt{Start} value to that value (rounded); the other variables stay free. The copy keeps the parameters of the original, except \texttt{OutputFlag} $= 0$, \texttt{LogToConsole} $= 0$, \texttt{LogFile} empty and \texttt{TimeLimit} $=$ the time limit above. Optimise the copy. Record its Gurobi runtime in \texttt{runtime\_seconds}.
  \item If the copy has a solution (at least one), set \texttt{Start} of every variable of the original model to its value in the copy; the status is \texttt{"completed"}.
  \item Otherwise record the status of the copy. If it is infeasible, compute an irreducible infeasible subset (IIS, Gurobi \texttt{computeIIS}) of the copy and record the names of at most $50$ of its linear rows and general constraints.
  \item If Gurobi raises an error in steps 1 to 3, the status is \texttt{"error"}, \texttt{values\_copied} is $0$ and \texttt{iis\_constraints} is empty.
\end{enumerate}
The copy is disposed of in every case. The original model is not changed; a failed completion, an error included, does not stop the solve.

\subsection{Relaxation Start}
\label{sec:warm_relaxation}

\blockhead{Condition}
\begin{itemize}[nosep,leftmargin=1.5em]
  \item The run option \texttt{relaxation\_warm\_start} (Section~\ref{sec:run_options}) is true.
  \item No start or hint was applied (\texttt{applied} is false in the report \texttt{warm\_start}).
\end{itemize}

\blockhead{Steps}
\begin{enumerate}[nosep,label=\arabic*.]
  \item Copy the model and relax its linear rows with Gurobi's \texttt{feasRelaxS} (type: sum of absolute violations; no minimal relaxation). The objective of the copy is the sum of the violations only; the original objective is dropped. Integrality, variable bounds, quadratic rows and general constraints are kept unchanged.
  \item Optimise the copy with the time limit $\max\{1,\ \texttt{relaxation\_time\_limit}\}$ seconds and the MIP gap $0.05$. The copy keeps the other parameters of the original, the logging included.
  \item Record the Gurobi runtime of the copy in \texttt{runtime\_seconds} and its status, as a string, in \texttt{status}. If the copy has a solution, record its objective in \texttt{relaxation\_objective} and set \texttt{Start} of every binary and integer variable of the original model to the rounded value of the variable of the same name in the copy.
  \item If Gurobi raises an error in steps 1 to 3, the status is \texttt{"error"}, \texttt{relaxation\_objective} is \texttt{null} and \texttt{values\_copied} is $0$.
\end{enumerate}
The copy is disposed of in every case. The relaxed solution need not be feasible for the original model. An error does not stop the solve.

\subsection{Warm Starts in Sweeps}
\label{sec:warm_sweeps}

\begin{itemize}[nosep,leftmargin=1.5em]
  \item With \texttt{warm\_start=True}, the source of a case is the result of the nearest preceding case of the same $H_1$ that has a solution, used in the mode \texttt{warm\_start\_mode}.
  \item The first case of each $H_1$ has no source.
  \item A case with an error or without a solution is never a source.
  \item \textbf{Test for a source}: the result of the case has \texttt{x} (not \texttt{null}). The source holds \texttt{H1}, \texttt{H2}, \texttt{x}, \texttt{m} and \texttt{r} of that result, and no completion request.
  \item The test for a feasible case (Section~\ref{sec:sweep_criteria}) is a different one: the row has an objective and an allowed status.
\end{itemize}

\label{sec:greedy}

\blockhead{Keys of the returned source}
\tabstart{p{5.2cm}p{9.8cm}}{Key & Content}
\rejrow{\texttt{H1}, \texttt{H2}, \texttt{x}, \texttt{m}, \texttt{r}}{as in a source (Section~\ref{sec:warm_interface})}
\rejrow{\texttt{complete\_binary\_start}}{\texttt{true}}
\rejrow{\texttt{completion\_time\_limit}}{$60$}
\tabend

\blockhead{Steps of the construction pass}
A proxy state $\hat s_{i\ell}$ starts at $\mu_{0,i\ell}$. For each day $k = 1,\ldots,T$:
\begin{enumerate}[nosep,label=\arabic*.]
  \item Order the missions by decreasing $\max_{i,\ell} \mu^{\inc}_{i\ell jk}/\tau_{i\ell}$; a tie goes to the larger $j$.
  \item In this order, give each mission to the train $i$ without a mission on day $k$ that minimises, in lexicographic order,
    $\bigl(\max_\ell (\hat s_{i\ell} + \mu^{\inc}_{i\ell jk})/\tau_{i\ell},\ \sum_\ell (\hat s_{i\ell} + \mu^{\inc}_{i\ell jk})/\tau_{i\ell}\bigr)$; a tie goes to the smaller $i$.
    Add $\mu^{\inc}_{i\ell jk}$ to $\hat s_{i\ell}$. The check $F > M$ (Section~\ref{sec:consistency_checks}) guarantees a train for every mission.
  \item A train without a mission is idle, unless some component has $\hat s_{i\ell} > r\,\tau_{i\ell}$: then $x_{i0k} = 1$, and every such component is repaired ($x^m_{i\ell k} = 1$, $\hat s_{i\ell} \leftarrow (1-\rho_{i\ell})\,\hat s_{i\ell}$ for every repair law).
\end{enumerate}
The construction pass schedules no replacement.

\blockhead{Steps of the loop pass}
For each cell:
\begin{enumerate}[nosep,label=\arabic*.]
  \item Compute the reference trajectory $\zeta$ (Section~\ref{sec:encoding}) of the current schedule from the initial values, starting anchors and replacement values of the inputs.
  \item Compute the excess $e$ of the cell: the largest of
    \begin{itemize}[nosep]
      \item the loop excesses $\max\{0,\ \zeta^{q}_{T} - \zeta^{q}_{H_1}\}/M_q$ of every tracked quantity and anchor $q$ with natural range $M_q$ (Section~\ref{sec:loop});
      \item the violations of the reliability row on every day, divided by the natural range of the bounded quantity;
      \item the violations of the side row $\mu \le \bar\mu_{\mathrm{side}}$ and, where \texttt{v\_max\_user} is given, of $v \le V^{\mathrm{user}}_{\max}$, divided by $\tau$ and by the natural range of $v$.
    \end{itemize}
    The row is taken in the form built at the cell (Sections~\ref{sec:dyn_gaussian}--\ref{sec:dyn_rainflow}): the exact row for \texttt{"exact"}, the tangent row for \texttt{"tangent"}, and for \texttt{"pwl"} the cap of the segment that contains the mean of the day (where two segments contain it, at a boundary, their caps agree; the first segment for a negative mean and the last segment for a mean above $\tau$, with the tangent of the segment taken at the mean itself) (Section~\ref{sec:linear_forms}).
  \item While $e > 10^{-10}$: for every free day $k \in \{H_1+1,\ldots,T\}$ (the train has no mission, the cell no intervention), put a repair of the cell on day $k$ (the train goes to the depot) and recompute $e$; keep the repair with the smallest $e$, a tie to the later day.
  \item If no repair lowers $e$ by more than $10^{-10}$ and replacement is allowed, repeat the trial with a replacement.
  \item If no trial lowers $e$, count one failure for the cell and go to the next cell.
\end{enumerate}
The loop excess compares the reference trajectory on day $T$ with day $H_1$. This is stricter than the loop rows (Section~\ref{sec:loop}), which compare day $T$ with the start of the repetition $y$, and $y$ is at least the state on day $H_1$.
At a Wiener cell, steps 3 and 4 form one trial: on every free day, put a repair and, if replacement is allowed, a replacement, and recompute $e$ after each; keep the intervention with the smallest $e$, a tie to the repair, then to the later day.
A start with failures is returned.

\blockhead{Report keys}
\texttt{GreedyWarmStartReport.as\_dict()} returns plain Python types.
\tabstart{p{5.2cm}p{9.8cm}}{Key & Content}
\rejrow{\texttt{repairs}}{the number of ones in \texttt{m}}
\rejrow{\texttt{replacements}}{the number of ones in \texttt{r}}
\rejrow{\texttt{repeatability\_feasible}}{true without a failure}
\rejrow{\texttt{repeatability\_failures}}{the number of cells with a failure}
\rejrow{\texttt{maximum\_repeatability\_excess}}{the largest excess term of a cell before the division by the natural ranges, over all cells, after the loop pass}

\section{Validation Tools}
\label{sec:validation}
% ================================================================

The tools check a saved result against its input. They do not call the optimiser. Each tool:
\begin{itemize}[nosep]
  \item reads the input with the input reader and \texttt{load\_config} (Section~\ref{sec:data_flow});
  \item reads a result file in any format that \texttt{solve()} writes.
\end{itemize}
The dashboards and the validators of the Gamma model take the model of each cell from the result key \texttt{model}. The structural validator does not read this key.

\subsection{Tolerance of the checks}
\label{sec:validation_tolerance}

A binary that Gurobi accepts within \texttt{IntFeasTol} inside a big-M row can move a tracked state by $\texttt{IntFeasTol} \times M_s$, with $M_s$ the natural range of the state at the cell (Section~\ref{sec:encoding}); the defaults below allow for it.
The structural validator and the Gamma validators resolve the tolerance of each check in this order:
\begin{enumerate}[nosep,label=\arabic*.]
  \item The explicit argument (\texttt{tol} or \texttt{tolerance}), if it is not \texttt{None}: one value for every check.
  \item Else the key \texttt{tolerance} of the input block \texttt{validation} (Section~\ref{sec:run_options}), a finite number $> 0$: one value for every check.
  \item Else a default per check, from \texttt{FeasibilityTol} and \texttt{IntFeasTol} of \texttt{gurobi\_params} (names matched without regard to case; if absent, Gurobi's defaults $10^{-6}$ and $10^{-5}$), by the table below.
\end{enumerate}

\tabstart{p{7.0cm}p{8.0cm}}{Check on & Default tolerance}
\rejrow{a tracked quantity, an anchor, a start value, $z$, the cap of a cell}{$\texttt{FeasibilityTol} + \texttt{IntFeasTol} \cdot M_s$, with $M_s$ the natural range of the quantity at the cell; $\texttt{FeasibilityTol}$ where the range is not defined}
\rejrow{binaries}{\texttt{IntFeasTol}}
\rejrow{a probability or a cost}{\texttt{FeasibilityTol}}
\tabend

A check over several cells passes when no cell exceeds its own tolerance.
The dashboards pass the tolerance of their sidebar as the explicit argument.

\blockhead{Checks}
\begin{itemize}[nosep]
  \item \textbf{Status rule.} The status is not a check. A feasible incumbent is validated like an optimal solution, and the report echoes the status.
  \item \textbf{Pass rule.} A check passes if no cell has a violation above its tolerance (Section~\ref{sec:validation_tolerance}). The checks \texttt{binary}, \texttt{one\_activity}, \texttt{mission\_coverage}, \texttt{depot\_gating} and \texttt{idle} use the tolerance for binaries, the checks \texttt{loop\_}$q$ the tolerance of a tracked quantity at the cell, and \texttt{objective} the tolerance for a cost. \end{itemize}

\tabstart{p{2.6cm}p{7.2cm}p{5.2cm}}{Check & Condition & Violation}
\typerow{\texttt{binary}}{$x$, $x^m$, $x^r$ take only the values $0$ and $1$}{the largest distance of an entry from $\{0,1\}$}
\typerow{\texttt{one\_activity}}{$\sum_{j=0}^{M} x_{ijk} \leq 1$ (Section~\ref{sec:assignment})}{$\max\{0,\ \max_{i,k}(\sum_j x_{ijk} - 1)\}$}
\typerow{\texttt{mission\_coverage}}{every mission $j = 1,\ldots,M$ has $\sum_{i} x_{ijk} = 1$ (the depot $j = 0$ is not summed)}{$\max_{j \geq 1,k} |\sum_i x_{ijk} - 1|$}
\typerow{\texttt{depot\_gating}}{$x^m_{i\ell k} + x^r_{i\ell k} \leq x_{i0k}$ (Section~\ref{sec:depot}), and $x^r = 0$ if \texttt{allow\_replacement} is false}{$\max\{0,\ \max(x^m_{i\ell k} + x^r_{i\ell k} - x_{i0k})\}$; if \texttt{allow\_replacement} is false, the larger of this value and $\max r_{i\ell k}$}
\typerow{\texttt{idle}}{listed only if the result has the key \texttt{idle}, not \texttt{null} (Section~\ref{sec:output})}{$\max |\texttt{idle}_{i\ell k} - (x_{i0k} - x^m_{i\ell k} - x^r_{i\ell k})|$}
\typerow{\texttt{loop\_}$q$}{for $q \in \{\texttt{mu}, \texttt{v}, \texttt{R}, \texttt{K}, \texttt{g\_mu}, \texttt{g\_v}, \texttt{g\_R}, \texttt{g\_K}\}$: the loop rows $q_{i\ell T} \leq y^q_{i\ell}$ and $q_{i\ell H_1} \leq y^q_{i\ell}$ (Section~\ref{sec:loop}), where $y^q_{i\ell}$ is the saved start of the repetitions, the result key \texttt{y\_}$q$ (Section~\ref{sec:output}); without that key, the row $q_{i\ell T} \leq q_{i\ell H_1}$; \texttt{NaN} and \texttt{null} entries are skipped}{with \texttt{y\_}$q$: $\max\{0,\ \max(q_{i\ell T} - y^q_{i\ell}),\ \max(q_{i\ell H_1} - y^q_{i\ell})\}$; without: $\max\{0,\ \max(q_{i\ell T} - q_{i\ell H_1})\}$; maxima over $i,\ell$}
\typerow{\texttt{objective}}{the saved objective $o$ is not below the recomputed objective $r$}{$\max\{0,\ r - o\}/\max\{1, |o|\}$}
\tabend

The recomputed objective is Eq.~\eqref{eq:a_objective} in the objective mode of the input, with the day cost of Eq.~\eqref{eq:a_daycost} on the saved $x$, $z$ ($0$ where \texttt{NaN}) and $x^r$, the costs of the input, and the saved $u$.

The key \texttt{y\_}$q$ counts as saved if it holds at least one number. A difference of the table that is not a number is skipped. The report lists the checks in the order of the table. The eight checks \texttt{loop\_}$q$ are always listed; a check whose key is absent, or has no pair of numbers at days $H_1$ and $T$, has violation $0$. The internal function \texttt{check\_result(cfg, result, tol=None) -> dict} runs the checks, and the errors on sizes, shapes and arrays, on a \texttt{FleetConfig} and a result dictionary, and returns the report without writing it; \texttt{validate} and the dashboards call it.

\subsection{Validators of the Gamma Model}
\label{sec:validation_gamma}

\blockhead{Common rules}
These rules hold for each validator of this subsection.
\begin{itemize}[nosep]
  \item \textbf{Inputs.} A validator takes the normalised configuration \texttt{cfg} (\texttt{load\_config}) and the result dictionary. It returns a report of plain Python types.
  \item \textbf{File version.} The replay validator, the exact validator and the dispatcher have a file version. It takes an input path, a result path and \texttt{report\_path} (default \texttt{None}). It writes the report as YAML or JSON and creates the folder. The Monte Carlo validator has no file version; the file version of the dispatcher with mode \texttt{"stochastic"} serves it.
  \item \textbf{Tolerance.} \texttt{tolerance} (default \texttt{None}) must be positive if it is given. With \texttt{None}, the key \texttt{tolerance} of the block \texttt{validation} applies if present, else the defaults per check (Section~\ref{sec:validation_tolerance}). A check over several cells passes when no cell exceeds its own tolerance. The report key \texttt{tolerance} is the single value, or the mapping \texttt{\{FeasibilityTol, IntFeasTol\}}.
  \item \textbf{Gamma cells.} The Gamma cells are the cells whose entry of the result key \texttt{model} is \texttt{gamma}; this key must have the shape $F \times L$ and equal the input key \texttt{model}.
  \item \textbf{Event of a day.} The event of a cell on day $k$ is \texttt{"replacement"} if $x^r_{i\ell k} = 1$, else \texttt{"repair"} if $x^m_{i\ell k} = 1$, else \texttt{"mission"} if train $i$ flies a mission, else \texttt{"idle"}. Every validator applies it, also on a day with a global violation.
  \item \textbf{Indices.} In a report, \texttt{i}, \texttt{l} and \texttt{k} are 0-based array indices; \texttt{k} is day $k+1$.
  \item \textbf{Order of a file version.} It checks the suffix of \texttt{report\_path} before it reads a file, reads the result with \texttt{read\_result}, writes the report with \texttt{null} for a value that is not finite, and only then raises the \texttt{AssertionError}.
\end{itemize}

\blockhead{Errors}
\tabstart{p{3.4cm}p{11.6cm}}{Exception & Raised when}
\rejrow{\texttt{ValueError}}{\texttt{report\_path} has another suffix than YAML or JSON; \texttt{cfg} has no Gamma cell; the result has no key \texttt{model}, or its \texttt{model} has another shape than $F \times L$ or differs from the input at a cell; a required array is missing, has a wrong shape, or has a non-finite entry at a cell where it is read (an entry $\pm\infty$ of \texttt{z} at a Gamma cell raises; an entry \texttt{NaN} of \texttt{z} means that the row is not built, and is skipped); an array that must be binary is not within the tolerance for binaries of $\{0,1\}$}
\rejrow{\texttt{AssertionError}}{\texttt{raise\_on\_failure=True} and the report has \texttt{valid = false}}
\tabend

\subsubsection{Replay validator}

It reads \texttt{x}, \texttt{m}, \texttt{r} (optional), \texttt{mu}, \texttt{z} and, for $\ARDone$ cells, \texttt{g\_mu}. It also reads \texttt{y\_mu} and, for $\ARDone$ cells, \texttt{y\_g\_mu} if the result has them; each must have the shape $F \times L$.

\begin{lstlisting}[language=Python]
validate_gamma_replay_schedule(cfg, result, *, tolerance=None,
                               raise_on_failure=False) -> dict
validate_gamma_replay_files(input_path, result_path, report_path=None,
                            **kwargs) -> dict
\end{lstlisting}

\blockhead{Steps}
\begin{enumerate}[nosep,label=\arabic*.]
  \item Collect the global violations (strings in \texttt{global\_violations}) over every cell of the fleet, one string per occurrence:
  \begin{itemize}[nosep]
    \item a result horizon other than $T$, or a result without the key \texttt{T};
    \item a train with more than one activity;
    \item a mission not covered exactly once;
    \item a repair and a replacement of a cell on one day;
    \item an intervention on a day with a mission or without a depot day.
  \end{itemize}
  \item For each Gamma cell and day $k$, compute the reference trajectory of $\mu$ and $g^{\mu}$ (Section~\ref{sec:encoding}) from the saved schedule, starting at $\mu_0$ and, under $\ARDone$, at the starting anchor $g^{\mu}_0$, with the replacement value of the cell.
  \item Set the event of the day: \texttt{"replacement"}, \texttt{"repair"}, \texttt{"mission"} or \texttt{"idle"}.
  \item Compute the errors of the fields below.
  \item If an error is above the tolerance of its cell (the tolerance of a tracked quantity at the cell, for all five fields), add a record \texttt{i}, \texttt{l}, \texttt{k}, \texttt{event}, \texttt{field}, \texttt{expected}, \texttt{saved}, \texttt{error} to \texttt{violations}.
\end{enumerate}

\blockhead{Error fields}
\tabstart{p{3.4cm}p{11.6cm}}{Field & Error}
\rejrow{\texttt{tracked\_mean}}{$\max\{0,\ \text{reference mean} - \texttt{mu}_{i\ell k}\}$}
\rejrow{\texttt{mean\_anchor}}{the same for \texttt{g\_mu}, under $\ARDone$}
\rejrow{\texttt{removed\_mean}}{$\max\{0,\ x^m_{i\ell k}\,\rho_{i\ell}(\mu_{i\ell,k-1} - g_{i\ell,k-1}) - z_{i\ell k}\}$ on the saved \texttt{mu} and \texttt{g\_mu} (on day~1: $\mu_0$ and $g^{\mu}_0$), with $g = 0$ under $\ARDinf$ (Section~\ref{sec:repair_cost}); skipped where $z$ is \texttt{NaN} ($C_{R,i\ell} = 0$)}
\rejrow{\texttt{cap}}{$\max\{0,\ \texttt{mu}_{i\ell k} - A_1(\beta^*\tau,\varepsilon)/\beta^*\}$ (Section~\ref{sec:dyn_gamma}); the cap is $\tau_{i\ell}$ at a cell in which no term has a rate}
\rejrow{\texttt{repeatability}}{with $y^{\mu}_{i\ell}$ saved and a number at the cell: $\max\{0,\ \texttt{mu}_{i\ell T} - y^{\mu}_{i\ell},\ \texttt{mu}_{i\ell H_1} - y^{\mu}_{i\ell}\}$; otherwise $\max\{0,\ \texttt{mu}_{i\ell T} - \texttt{mu}_{i\ell H_1}\}$. In a record, \texttt{expected} is the reference value, the cap (\texttt{cap}), or the limit of \texttt{repeatability}: $y^{\mu}_{i\ell}$ (or $y^{g,\mu}_{i\ell}$), else the saved value on day $H_1$. A \texttt{repeatability} record is on day $T$ with its event, and its \texttt{saved} is the saved value on day $T$. For the other fields, \texttt{saved} is the saved value that the field compares (\texttt{mu}, \texttt{g\_mu} or \texttt{z}).

\textbf{Pass rule.} \texttt{valid} is true if there is no global violation and no violation.

\subsubsection{Exact validator}

Module \texttt{gamma\_utils.gamma\_tail\_validator}, not exported.

\begin{lstlisting}[language=Python]
validate_gamma_tail_bound_schedule(cfg, result, *, tolerance=None,
    convolution_tolerance=1e-12, max_series_terms=100000,
    include_steps=False, raise_on_failure=False) -> dict
validate_gamma_tail_bound_files(input_path, result_path, report_path=None,
                                **kwargs) -> dict
\end{lstlisting}

\blockhead{Further arguments}
\tabstart{p{4.3cm}p{2.3cm}p{8.2cm}}{Argument & Default & Rule}
\typerow{\texttt{convolution\_tolerance}}{\texttt{1e-12}}{Must lie in $(0,1)$; bound on the remaining mixture mass of the series}
\typerow{\texttt{max\_series\_terms}}{\texttt{100000}}{Must be positive and an integer; a number with zero fractional part is accepted, a flag is not; maximum number of series terms}
\typerow{\texttt{include\_steps}}{\texttt{False}}{With \texttt{True}, the report holds the list \texttt{steps}}
\tabend

\blockhead{Steps}
For each Gamma cell and day $k = 1,\ldots,T$:
\begin{enumerate}[nosep,label=\arabic*.]
  \item Keep the true damage as a list of independent Gamma terms (Section~\ref{sec:dyn_gamma}) and update it with the event of the day:
  \begin{itemize}[nosep]
    \item a mission adds a term with the exact rate of its increment;
    \item a repair multiplies the rate of the repairable terms by $1/(1-\rho)$, and removes them for $\rho = 1$; under $\ARDone$ the repaired terms join the frozen part of the anchor;
    \item a replacement starts a new list with the replacement term.
  \end{itemize}
  Under $\ARDone$ the initial damage is a frozen part of mean $g^{\mu}_0$ and a repairable part of mean $\mu_0 - g^{\mu}_0$, both with rate $\beta_0$ or both constants; a replacement term is frozen. A repair multiplies a repairable constant by $1 - \rho$.
  \item Treat an initial or replacement damage without a rate (\texttt{gamma\_beta\_0} or \texttt{gamma\_beta\_new} omitted) as a known constant $c$, not as a term. The tail is then $\Pr(\text{sum of the terms} > \tau - c)$; it is $1$ if $c \ge \tau$ and some term exists; without terms it is $1$ if $c > \tau$, else $0$.
  \item Compute the tail $\Pr(D_k > \tau)$ by the Moschopoulos series (with equal rates, the Gamma tail). The rates are equal if \texttt{numpy.allclose} holds with relative tolerance $10^{-13}$ and absolute tolerance $0$; the tail is then one Gamma tail, with remaining mass $0$ and $1$ series term.
  \item Take as upper bound the partial sum plus the remaining mixture mass, which is at most \texttt{convolution\_tolerance}.
  \item The weights, the mass and the tail of the series are summed in \texttt{numpy.longdouble}. The weights are computed in log scale, so a small first weight causes no error.
\end{enumerate}

\blockhead{Pass rule}
A day passes if:
\begin{itemize}[nosep]
  \item the upper bound is at most $\varepsilon_{i\ell}$ plus the tolerance for a probability;
  \item the saved mean is at least $\mathbb{E}D_k$ minus the tolerance of a tracked quantity at the cell;
  \item under $\ARDone$, the saved anchor is at least the exact mean of the frozen part minus the tolerance of a tracked quantity at the cell.
\end{itemize}
\texttt{valid} is true if there is no global violation (step 1 of the replay validator) and every day passes. A failed condition adds a record with the keys of the replay record, with field \texttt{reliability} (\texttt{expected} $\varepsilon_{i\ell}$, \texttt{saved} the upper bound), \texttt{tracked\_mean} (\texttt{expected} $\mathbb{E}D_k$) or \texttt{mean\_anchor} (\texttt{expected} the exact mean of the frozen part); \texttt{maximum\_errors} has these three fields, and the keys \texttt{tolerance} and \texttt{maximum\_error\_tolerances} are those of the replay report.

\rejrow{\texttt{ValueError}}{\texttt{convolution\_tolerance} is not in $(0,1)$; \texttt{max\_series\_terms} is not a positive integer}
\rejrow{\texttt{RuntimeError}}{the series does not reach \texttt{convolution\_tolerance} within \texttt{max\_series\_terms} terms (the series needs at least $2$ terms if the rates differ)}
\tabend

\blockhead{Report keys}
\tabstart{p{5.2cm}p{9.8cm}}{Key & Content}
\rejrow{keys of the replay report}{all of them are included}
\rejrow{\texttt{minimum\_reliability\_slack}}{the minimum of $\varepsilon$ minus the upper bound}
\rejrow{\texttt{worst\_reliability}}{the step that attains the minimum}
\rejrow{\texttt{maximum\_remaining\_mass}}{maximum remaining mass}
\rejrow{\texttt{maximum\_series\_terms\_used}, \texttt{total\_series\_terms}, \texttt{exact\_tail\_evaluations}}{largest and total number of series terms; number of tails with at least one series term (a tail that is $0$ or $1$ by the constant alone has none); \texttt{timing} adds \texttt{exact\_tail\_seconds}}
\rejrow{\texttt{steps}}{with \texttt{include\_steps=True}, per cell and day: \texttt{i}, \texttt{l}, \texttt{k}, \texttt{event}, \texttt{epsilon}, \texttt{constant}, \texttt{exact\_mean}, \texttt{saved\_mean}, \texttt{frozen\_mean}, \texttt{saved\_anchor}, \texttt{exact\_tail\_estimate}, \texttt{exact\_tail\_upper\_bound}, \texttt{remaining\_mass}, \texttt{series\_terms}, \texttt{reliability\_slack}, \texttt{terms}; \texttt{frozen\_mean} and \texttt{saved\_anchor} are \texttt{null} outside $\ARDone$; \texttt{worst\_reliability} is the first step with the smallest slack}
\rejrow{\texttt{terms}}{the list of the Gamma terms of the day, in the order frozen part, then repairable part. A step of \texttt{steps} always has \texttt{terms}; \texttt{worst\_reliability} has it also without \texttt{include\_steps}}

\subsubsection{Monte Carlo validator}

The schedule is fixed, and only Gamma cells are sampled.

\begin{lstlisting}[language=Python]
validate_gamma_stochastic_schedule(cfg, result, *, repetitions=100000,
    random_seed=20260908, maximum_schedule_failure_rate=None,
    confidence_level=0.95, batch_size=20000, tolerance=None,
    raise_on_failure=False) -> dict
\end{lstlisting}

\blockhead{Further arguments}
\tabstart{p{4.3cm}p{2.3cm}p{8.2cm}}{Argument & Default & Rule}
\typerow{\texttt{repetitions}}{\texttt{100000}}{Number of runs; must be positive and an integer; a number with zero fractional part is accepted, a flag is not}
\typerow{\texttt{random\_seed}}{\texttt{20260908}}{Seed of the generator; the same arguments give the same samples; a non-negative integer; a number with zero fractional part is accepted, a flag is not; a negative value raises a \texttt{ValueError} that names the argument}
\typerow{\texttt{maximum\_schedule\_failure\_rate}}{\texttt{None}}{Target for the schedule failure rate; if given, must lie in $[0,1]$}
\typerow{\texttt{confidence\_level}}{\texttt{0.95}}{Must lie in $(0,1)$}
\typerow{\texttt{batch\_size}}{\texttt{20000}}{Draws are made in batches of this many runs; must be positive and an integer; a number with zero fractional part is accepted, a flag is not}
\tabend

\blockhead{Steps}
In each of \texttt{repetitions} runs:
\begin{enumerate}[nosep,label=\arabic*.]
  \item Draw the true damage of every Gamma cell. The initial damage, each mission increment and each replacement draw are independent Gamma variables with the means and rates of the inputs.
  \item Under $\ARDone$, take the initial damage as the sum of two independent terms with means $g^{\mu}_0$ (the anchor) and $\mu_0 - g^{\mu}_0$. A damage without a rate is the constant of its mean.
  \item Each day, apply the repair law to the sampled path: $D \leftarrow (1-\rho)\,D$ under $\ARDinf$; $D \leftarrow g + (1-\rho)(D - g)$, then $g \leftarrow D$, under $\ARDone$.
  \item On a replacement, draw the damage of the replacement part and, under $\ARDone$, set $g$ to it.
  \item After each day, record whether $D > \tau$.
\end{enumerate}
The validator raises no error for a global violation of the schedule; it applies the event of each day. The tolerance is used only for the binaries (the tolerance for binaries). The arguments used are \texttt{repetitions}, \texttt{random\_seed}, \texttt{maximum\_schedule\_failure\_rate}, \texttt{confidence\_level}, \texttt{batch\_size} and \texttt{tolerance}.

\blockhead{Definitions}
\begin{itemize}[nosep,leftmargin=1.5em]
  \item \textbf{Schedule failure}: a run in which some Gamma cell exceeds its threshold on some day.
  \item \textbf{Upper bound of a failure rate}: each failure rate (of the fleet, of a cell, of the worst day of a cell) comes with its one-sided Clopper--Pearson upper bound at \texttt{confidence\_level}. For $f$ failures in $n$ runs, it is the \texttt{confidence\_level}-quantile of the law Beta$(f+1,\ n-f)$, and $1$ if $f = n$.
\end{itemize}

\textbf{Pass rule.} \texttt{valid} is true if no target is given, or if the observed schedule failure rate is at most \texttt{maximum\_schedule\_failure\_rate}.

\rejrow{\texttt{validator}, \texttt{mode}, \texttt{valid}, \texttt{timing}}{validator, mode, result of the pass rule, timing}
\rejrow{arguments used}{the keys \texttt{repetitions}, \texttt{random\_seed}, \texttt{maximum\_schedule\_failure\_rate}, \texttt{confidence\_level}, \texttt{batch\_size} and \texttt{tolerance}, with the values used}
\rejrow{\texttt{scope}}{``Gamma cells only''}
\rejrow{\texttt{complete\_fleet\_validation}}{false if the fleet has other cells}
\rejrow{\texttt{excluded\_cells}}{for each other cell: \texttt{i}, \texttt{l}, \texttt{component}, \texttt{model}, \texttt{reason}}
\rejrow{\texttt{schedule}}{\texttt{failed\_replays}, \texttt{failure\_rate}, \texttt{failure\_rate\_upper\_confidence\_bound}, \texttt{maximum\_failure\_rate}, \texttt{observed\_target\_met}, \texttt{confidence\_qualified\_target\_met}}
\rejrow{\texttt{cells}}{for each Gamma cell: \texttt{i}, \texttt{l}, \texttt{component}, \texttt{repair\_model}, \texttt{threshold}, \texttt{analytical\_epsilon}, \texttt{failed\_replays}, \texttt{failure\_rate}, \texttt{failure\_rate\_upper\_confidence\_bound}, \texttt{worst\_time\_step}, \texttt{worst\_step\_failures}, \texttt{worst\_step\_failure\_rate}, \texttt{worst\_step\_upper\_confidence\_bound}, \texttt{maximum\_sampled\_damage}, \texttt{maximum\_threshold\_excess}; \texttt{worst\_time\_step} is the 0-based index of the day with the largest failure rate over the runs, and a tie goes to the earliest day; the three \texttt{worst\_step\_} keys are the failures, the rate and the upper bound of that day}
