\subsection{Data Flow of One Solve}
\label{sec:data_flow}

\begin{lstlisting}[language=Python]
solve(input_path, results_path="output.yaml", *,
      warm_start=None, warm_start_mode="start") -> dict
\end{lstlisting}
\begin{enumerate}[nosep,label=\arabic*.]
  \item Check the input file: it exists (\texttt{FileNotFoundError}) and has the extension \texttt{.yaml}, \texttt{.yml}, \texttt{.json}, \texttt{.h5} or \texttt{.hdf5} (\texttt{ValueError}). Check \texttt{results\_path} (Section~\ref{sec:output_files}).
  \item Read the file with the input reader (Section~\ref{sec:schema}) into a mapping.
  \item \texttt{load\_config}: normalise the mapping into a \texttt{FleetConfig} and run the checks of Section~\ref{sec:consistency_checks} (\texttt{ValueError}).
  \item Build the model (Section~\ref{sec:builders}), apply the warm start (Section~\ref{sec:warm_starts}) and optimise.
  \item Extract the result (Section~\ref{sec:output}): the shared extraction, then the \texttt{extract} hook of each builder. Write the result file (Section~\ref{sec:output_files}) and return the result.
\end{enumerate}
Steps 3 to 5 form the internal entry point \texttt{solve\_mapping(data, results\_path=None, *, warm\_start=None, warm\_start\_mode="start")}, which takes the mapping of step~2. Gurobi errors are not caught.

\subsection{Public API}
\label{sec:api}

The package exports:
\begin{itemize}[nosep]
  \item one solve: \texttt{solve} (Section~\ref{sec:data_flow});
  \item horizon sweeps: \texttt{sweep\_operating\_horizons} and \texttt{sweep\_horizon\_grid} (Section~\ref{sec:sweeps});
  \item plots: \texttt{plot\_management} and \texttt{plot\_horizon\_sweep} (Section~\ref{sec:plotting});
  \item the structural validator \texttt{validate} (Section~\ref{sec:validation_structural});
  \item the Gamma validators (Section~\ref{sec:validation_gamma}): the replay validator \texttt{validate\_gamma\_replay\_schedule} with its file version \texttt{validate\_gamma\_replay\_files}; the Monte Carlo validator \texttt{validate\_gamma\_stochastic\_schedule}; and the selector of both, \texttt{validate\_gamma\_schedule}, with its file version \texttt{validate\_gamma\_schedule\_files}.
\end{itemize}
Internal functions, not exported: \texttt{solve\_mapping} and \texttt{load\_config} (Section~\ref{sec:data_flow}); the greedy heuristic \texttt{build\_greedy\_warm\_start} (Section~\ref{sec:greedy}); the exact Gamma validator \texttt{validate\_gamma\_tail\_bound\_schedule} and its file version (Section~\ref{sec:validation_gamma}).

\subsection{Cell-Builder Interface}
\label{sec:builders}

A registry maps each model name (\texttt{gaussian}, \texttt{inverse\_gaussian}, \texttt{wiener}, \texttt{gamma}, \texttt{rainflow}) to a builder; the model of cell $(i,\ell)$ is its entry of \texttt{model}.
\begin{lstlisting}[language=Python]
register_cell_builder(name, builder)  # CELL_BUILDERS[name] = builder
get_cell_builder(name)    # NotImplementedError, with the names, if absent
dispatch_cell(ctx, i, l)  # get_cell_builder(ctx.model_of[i, l])
                          #     .add_cell(ctx, i, l)
\end{lstlisting}
A builder has the attribute \texttt{name} and three hooks:
\begin{itemize}[nosep]
  \item \texttt{prepare(ctx, cfg, cells, opts)}: called once per model in the fleet, with its cells. It stores the per-cell arrays of the model in \texttt{ctx}, creates the variables of the tracked quantities, anchors and selectors of these cells only, may tighten variable bounds, and sets Gurobi's \texttt{NonConvex} to $2$ if some cell keeps an exact quadratic row.
  \item \texttt{add\_cell(ctx, i, l)}: adds the rows of one cell (Section~\ref{sec:constraints}): dynamics in the form of \texttt{encoding}, replacement and anchor rows, repair-cost rows, reliability rows in the form of \texttt{reliability\_impl}, loop rows of the full tracked state.
  \item \texttt{extract(ctx, cfg, out)}, optional: adds model-specific entries to the result \texttt{out} after the shared entries.
\end{itemize}
The context \texttt{ctx} holds the sizes $F$, $L$, $M$, $H_1$, $H_2$, $T$; the Gurobi model; the shared variables $x$, $x^m$, $x^r$ (absent if replacement is not allowed), $\mu$, $z$ (cells with $C_R > 0$) and $u$ (if $C_D > 0$), with the shapes of Section~\ref{sec:variables}; the per-cell arrays (model, $\tau$, $\varepsilon$, $\rho$, initial and replacement values, starting anchors); the increment accessor $(i, j, \ell, k) \mapsto$ increment after the phase lookup, Eq.~\eqref{eq:c_phase}, with $j = 0$ the depot; the run options; a dictionary \texttt{extras}.

Building order:
\begin{enumerate}[nosep,label=\arabic*.]
  \item Create the model, apply the run options, create the shared variables.
  \item Call \texttt{prepare} for each model present, in alphabetical order of the names.
  \item Build the objective (Section~\ref{sec:objective}) and the rows that do not depend on the model: assignment (Section~\ref{sec:assignment}), depot day (Section~\ref{sec:depot}), damage penalty (Section~\ref{sec:damage_reg}).
  \item Call \texttt{add\_cell} for every cell, $i$ outer, $\ell$ inner.
\end{enumerate}
Each builder defines $\mu_{i\ell k}$, $k = 1,\ldots,T$, for its cells. A model is added by a module with its builder, its registration, its input checks in \texttt{config.py} (Section~\ref{sec:consistency_checks}) and its section in this specification.

\section{Horizon Sweeps}
\label{sec:sweeps}
% ================================================================

A horizon sweep solves one input for several pairs $(H_1, H_2)$ and ranks the cases. \texttt{sweep\_operating\_horizons} varies $H_2$ for one $H_1$; \texttt{sweep\_horizon\_grid} varies $H_1$ and $H_2$.
No input key starts a sweep, and \texttt{solve()} never runs one.

\subsection{Cost Measures and Ranking}
\label{sec:sweep_criteria}

$J_{\mathrm{init}}$ and $J_{\mathrm{op}}$ of a case are Eq.~\eqref{eq:a_phases} on its solution. The cost per operating day, and the projected cost over an evaluation horizon $E > H_1$, are
\begin{equation}
  \bar J_{\mathrm{op}} = J_{\mathrm{op}} / H_2, \qquad
  P_E = J_{\mathrm{init}} + (E - H_1)\,\bar J_{\mathrm{op}} .
  \label{eq:d_projected}
\end{equation}
A case is \emph{feasible} if its result holds a solution and its status is not \texttt{"infeasible"}, \texttt{"unbounded"} or \texttt{"inf\_or\_unbounded"}.
A case is \emph{proven} if it is feasible and its status is \texttt{"optimal"} at the MIP gap used for the case: Gurobi's \texttt{MIPGap} after all options are set, \texttt{gurobi\_params} included (Section~\ref{sec:run_options}); it is the entry \texttt{requested\_mip\_gap} of \texttt{performance}.
The \emph{ranking value} is $\bar J_{\mathrm{op}}$ in \texttt{sweep\_operating\_horizons}; in \texttt{sweep\_horizon\_grid} it is $P_E$ if an evaluation horizon is given, otherwise $\bar J_{\mathrm{op}}$.
The \emph{best proven case} and the \emph{best feasible case} have the smallest ranking value among the proven and the feasible cases. A tie goes to the smaller $H_2$; in the grid, to the smaller $H_1$, then the smaller $H_2$.

\subsection{\texttt{sweep\_operating\_horizons}}
\label{sec:sweep_operating}

\begin{lstlisting}[language=Python]
sweep_operating_horizons(
    input_path, operating_horizons, *, output_path=None,
    stop_on_gradient=False, gradient_tolerance=1e-3,
    flat_gradients_required=2, minimum_cases=3,
    maximum_mip_gap_for_stopping=None,
    warm_start=False, warm_start_mode="start", n_workers=1,
    objective_mode="operating_average", evaluation_horizon=None) -> dict
\end{lstlisting}
Arguments with a rule:
\begin{itemize}[nosep]
  \item \texttt{input\_path}: $H_1$ is the first entry of \texttt{H}, or \texttt{H} if it is a scalar; the second entry is ignored.
  \item \texttt{operating\_horizons}: the values of $H_2$; positive integers, at least one, no duplicates; evaluated in increasing order.
  \item \texttt{output\_path}: the report file, \texttt{.yaml} or \texttt{.yml}; missing parent folders are created; \texttt{None} writes no file.
  \item The arguments of the early stop (Section~\ref{sec:sweep_stop}): \texttt{gradient\_tolerance} is finite and $\ge 0$; \texttt{flat\_gradients\_required} is $\ge 1$; \texttt{minimum\_cases} is $\ge 2$; \texttt{maximum\_mip\_gap\_for\_stopping} is \texttt{None} or a finite number $\ge 0$.
  \item \texttt{objective\_mode}, \texttt{evaluation\_horizon}: written into every case input; \texttt{"evaluation\_total"} needs $E > H_1$. For \texttt{warm\_start}, \texttt{warm\_start\_mode} and \texttt{n\_workers}, see Sections~\ref{sec:warm_sweeps} and~\ref{sec:sweep_parallel}.
\end{itemize}
Steps:
\begin{enumerate}[nosep,label=\arabic*.]
  \item Read the input file with the input reader (Section~\ref{sec:schema}); the data must be a mapping (\texttt{TypeError}). Check every argument.
  \item For each $H_2$, the case input is the input data with \texttt{H} $= [H_1, H_2]$, and with \texttt{objective\_mode} and \texttt{evaluation\_horizon} (if given) replaced. Time-indexed data are not interpolated: a profile whose length is not $H_2$ fails the checks of Section~\ref{sec:consistency_checks}, as an error of that case.
  \item Solve the case input with \texttt{solve\_mapping} (Section~\ref{sec:data_flow}) and \texttt{results\_path=None}; no temporary file is written. Keep the row of the case, not its schedule.
  \item After each case: append its row, annotate the gradient (Section~\ref{sec:sweep_stop}), test the stop rule, write a checkpoint if \texttt{output\_path} is given. At the end, write the final report and return it.
\end{enumerate}
\emph{Errors.} \texttt{ValueError} before the first case for an invalid argument, for a list \texttt{H} whose length is not two, and for \texttt{warm\_start} or \texttt{stop\_on\_gradient} with $\texttt{n\_workers} > 1$; such an error is never recorded as a case error. An error inside a case is captured in its row (Section~\ref{sec:sweep_report}).

\subsection{Early Stop}
\label{sec:sweep_stop}

Let $\bar J_n$ be the cost per operating day of the $n$-th evaluated case. If cases $n-1$ and $n$ are feasible, the relative gradient is
\begin{equation}
  \hat g_n = \frac{\bar J_n - \bar J_{n-1}}{(H_{2,n} - H_{2,n-1})\,\max\{\,|\bar J_{n-1}|,\ \varepsilon_{\mathrm{mach}}\}},
  \label{eq:d_gradient}
\end{equation}
with $\varepsilon_{\mathrm{mach}}$ the machine precision of double-precision numbers.
With $t = \texttt{gradient\_tolerance}$, the \emph{class} of case $n$ is \texttt{"increase"} if $\hat g_n > t$, \texttt{"decrease"} if $\hat g_n < -t$, \texttt{"flat"} otherwise, and \texttt{"unavailable"} if $n = 1$ or one of the two cases is not feasible.
A case \emph{qualifies} if it reports a finite MIP gap at most its threshold: \texttt{maximum\_mip\_gap\_for\_stopping} if it is a number, otherwise the MIP gap used for the case (\texttt{requested\_mip\_gap} of its row). The gradient of case $n$ is \emph{eligible to stop} if cases $n-1$ and $n$ qualify.
Every row carries its gradient, class and eligibility, also if \texttt{stop\_on\_gradient} is false. With \texttt{stop\_on\_gradient=True} the sweep stops after case $n$ if $n \ge \texttt{minimum\_cases}$, the gradient of case $n$ is eligible, and either the class of case $n$ is \texttt{"increase"} (reason \texttt{"cost\_increase"}) or the last \texttt{flat\_gradients\_required} cases up to $n$ all have the class \texttt{"flat"} and an eligible gradient (reason \texttt{"flat\_gradient"}).
The last candidate of \texttt{operating\_horizons} is a hard limit.

\subsection{Report, Checkpoint and Errors}
\label{sec:sweep_report}

The report is a mapping of plain Python types, written as YAML. \emph{Keys:} \texttt{input} (input path); \texttt{complete} (\texttt{false} in a checkpoint); \texttt{last\_completed\_H2}; \texttt{objective} (a text); \texttt{varied\_parameter} (\texttt{"H2"}); \texttt{fixed\_dimensions} ($F$, $M$, $L$) and \texttt{H1}; \texttt{planned\_operating\_horizons} and \texttt{evaluated\_operating\_horizons}; \texttt{warm\_start} (\texttt{enabled}, \texttt{mode}) and \texttt{n\_workers}; \texttt{stopping\_rule}, with \texttt{enabled}, \texttt{relative\_gradient\_tolerance\_per\_H2}, the stop arguments \texttt{flat\_gradients\_required}, \texttt{minimum\_cases} and \texttt{maximum\_mip\_gap\_for\_stopping} under their own names (the last one \texttt{null} for the default), the \texttt{reason} (\texttt{"in\_progress"}, \texttt{"candidate\_range\_exhausted"}, \texttt{"cost\_increase"} or \texttt{"flat\_gradient"}) and \texttt{stopped\_early} (complete with fewer cases than planned); \texttt{cases} (the rows, by $H_2$); \texttt{formulation\_growth} from the first to the last row with counts: \texttt{from\_H2}, \texttt{to\_H2}, \texttt{added\_time\_steps} and, for each count $q$ of \texttt{formulation}, \texttt{added\_}$q$ and $q$\texttt{\_per\_added\_time\_step} (\texttt{null} with fewer than two such rows); for $b \in \{$\texttt{proven}, \texttt{feasible}$\}$, \texttt{best\_}$b$\texttt{\_H2} and \texttt{best\_}$b$\texttt{\_J\_op\_average}, and \texttt{best\_feasible\_status} (\texttt{null} without such a case).

\emph{Keys of a case row:} \texttt{H1}, \texttt{H2}, \texttt{T}, \texttt{dimensions} ($F$, $M$, $L$, $H_1$, $H_2$, $T$); from the result of the case (Section~\ref{sec:output}), \texttt{status}, \texttt{objective\_mode}, \texttt{evaluation\_horizon}, \texttt{objective}, the scalar keys of the cost report, and the warm-start report \texttt{warm\_start}; \texttt{objective\_bound}, \texttt{mip\_gap} and \texttt{absolute\_mip\_gap} $= \max\{0,\ \text{objective} - \text{bound}\}$; \texttt{requested\_mip\_gap} and \texttt{requested\_time\_limit\_seconds}, Gurobi's \texttt{MIPGap} and \texttt{TimeLimit} after all options are set; \texttt{optimizer\_seconds}, \texttt{solutions\_found}; \texttt{formulation}, the size entries of \texttt{performance} from \texttt{variables} to \texttt{nonzeros}; \texttt{timing}, the wall-clock entries of \texttt{performance} with \texttt{branch\_and\_bound\_nodes}, \texttt{simplex\_iterations} and \texttt{work\_units}; the gradient keys \texttt{cost\_gradient\_per\_H2}, \texttt{relative\_cost\_gradient\_per\_H2}, \texttt{gradient\_classification} and \texttt{gradient\_stopping\_eligible} (Section~\ref{sec:sweep_stop}).

\emph{Checkpoint.} With \texttt{output\_path}, the report is rewritten after every case, with \texttt{complete = false} and the reason \texttt{"in\_progress"} until the sweep ends.

\emph{Case errors.} An exception (class \texttt{Exception}) raised by a case after the arguments are accepted is logged at level ERROR with $H_1$ and $H_2$. The row of the case has the status \texttt{"error: "} followed by the message, and \texttt{null} in every entry except the sizes; the sweep continues. Such a row is neither feasible nor proven, and is never a warm-start source.

\subsection{Parallel Cases}
\label{sec:sweep_parallel}

With $\texttt{n\_workers} > 1$, up to \texttt{n\_workers} cases are solved at the same time, each in its own process with its own Gurobi environment and one Gurobi licence token. The option is refused with \texttt{warm\_start} and with \texttt{stop\_on\_gradient}.
Rows arrive in the order of completion; the report orders them by $H_2$, and each rewrite recomputes the gradient annotations over the ordered rows.

\subsection{\texttt{sweep\_horizon\_grid}}
\label{sec:sweep_grid}

\begin{lstlisting}[language=Python]
sweep_horizon_grid(
    input_path, transitory_horizons, operating_horizons, *,
    output_path=None, warm_start=True, evaluation_horizon=None,
    **sweep_options) -> dict
\end{lstlisting}
Both horizon lists hold positive integers; they are sorted and repeated values are removed. \texttt{evaluation\_horizon}, if given, must exceed every $H_1$ (\texttt{ValueError}).
\texttt{sweep\_options} are the keyword arguments of \texttt{sweep\_operating\_horizons} except \texttt{objective\_mode}. With $\texttt{n\_workers} > 1$, \texttt{warm\_start=False} must be passed.

For each $H_1$ in increasing order, \texttt{sweep\_operating\_horizons} runs on the input data with that $H_1$ and the list of $H_2$, with \texttt{objective\_mode} \texttt{"evaluation\_total"} if an evaluation horizon is given and \texttt{"operating\_average"} otherwise.
Warm starts (Section~\ref{sec:warm_sweeps}), the early stop and the capture of case errors act within each $H_1$; the early stop uses $\bar J_{\mathrm{op}}$ also when $E$ is given. The grid report is rewritten after every case (\texttt{complete = false}) and at the end.

\emph{Keys:} \texttt{input}, \texttt{complete} and \texttt{objective} as in Section~\ref{sec:sweep_report}; \texttt{comparison\_metric}, the ranking key (\texttt{"projected\_evaluation\_cost"} or \texttt{"J\_op\_average"}); \texttt{mip\_certificate\_metric} (\texttt{"objective"}); \texttt{evaluation\_horizon}; \texttt{varied\_parameters} (\texttt{["H1", "H2"]}); \texttt{fixed\_dimensions} ($F$, $M$, $L$); the candidates \texttt{planned\_transitory\_horizons} and \texttt{planned\_operating\_horizons}; the flag \texttt{warm\_start\_enabled}; \texttt{H1\_sweeps}, the report of each operating sweep, with the input file of the grid as \texttt{input}; \texttt{cases}, all rows by $H_1$, then $H_2$; \texttt{best\_proven} and \texttt{best\_feasible}, \texttt{null} or a mapping with \texttt{H1}, \texttt{H2}, \texttt{T}, \texttt{status}, \texttt{mip\_gap}, \texttt{objective} and the scalar keys of the cost report except \texttt{J\_op} and \texttt{J\_total}.

\section{Warm Starts}
\label{sec:warm_starts}
% ================================================================

A warm start gives Gurobi values for the binary variables. Four mechanisms exist: a \emph{start} (attribute \texttt{Start}) from a source, with an optional completion; \emph{hints} (attribute \texttt{VarHintVal}) from a source; a \emph{relaxation start}; and the \emph{greedy heuristic}, which builds a source from the input.

\subsection{Interface and Reports}
\label{sec:warm_interface}
\label{sec:warm_reports}

\texttt{solve()} takes \texttt{warm\_start}, a source or \texttt{None} (default), and \texttt{warm\_start\_mode}: \texttt{"start"} (default), \texttt{"hint"} or \texttt{"both"}; another value raises \texttt{ValueError}.
A \emph{source} is a result dictionary or the dictionary returned by the greedy heuristic (Section~\ref{sec:greedy}). It carries \texttt{x} (shape $F' \times (M'+1) \times T'$) and the integers \texttt{H1}, \texttt{H2} with $T' = H_1' + H_2'$; it may carry \texttt{m} and \texttt{r} (shape $F' \times L' \times T'$).
A source whose \texttt{x} is missing or \texttt{null} has no effect. $F'$, $M'$, $L'$ may differ from $F$, $M$, $L$: values are set for the indices that both have.
The result keys \texttt{warm\_start} and \texttt{relaxation\_warm\_start} report what each mechanism did (Section~\ref{sec:output_reports}).

\subsection{Day Mapping}
\label{sec:warm_map}

Day $k \in \{1,\ldots,T\}$ takes the values of the source day
\begin{equation}
  \sigma(k) =
  \begin{cases}
    k, & k \leq \min\{H_1, H_1'\}, \\
    H_1' + 1 + \bigl(\max\{0,\ k - H_1 - 1\} \bmod H_2'\bigr), & \text{otherwise.}
  \end{cases}
  \label{eq:d_daymap}
\end{equation}
The mapped values, rounded to the nearest integer, are $x_{ijk} \leftarrow x'_{ij\sigma(k)}$ for $j = 0,\ldots,M$; $x^m_{i\ell k} \leftarrow m'_{i\ell\sigma(k)}$, or $0$ if the source has no \texttt{m}; and $x^r_{i\ell k} \leftarrow r'_{i\ell\sigma(k)}$ if \texttt{allow\_replacement} is true and the source has \texttt{r}.
A binary variable that these values fix through its defining rows (the selector $n_{i\ell k}$ of Eq.~\eqref{eq:a_ind_sum}) gets that value.

\subsection{Start, Hints and Completion}
\label{sec:warm_start_modes}

Mode \texttt{"start"} sets \texttt{Start} of every mapped variable; continuous variables get no value. Mode \texttt{"hint"} sets \texttt{VarHintVal} instead, with no \texttt{Start}, no completion and no \texttt{VarHintPri}. Mode \texttt{"both"} sets \texttt{Start} and \texttt{VarHintVal}. In the modes \texttt{"start"} and \texttt{"both"} the completion runs if the source requests it.

\emph{Completion.} Only the source requests it, with \texttt{complete\_binary\_start = true}; the greedy heuristic does. It runs if the mapping set at least one value, with the time limit \texttt{completion\_time\_limit} of the source (seconds, default $60$).
\begin{enumerate}[nosep,label=\arabic*.]
  \item Copy the model; fix every binary variable that has a \texttt{Start} value to that value; the other binary variables stay free. Optimise the copy within the time limit.
  \item If the copy has a solution, set \texttt{Start} of every variable of the original model to its value in the copy.
  \item Otherwise record the status of the copy. If it is infeasible, compute an irreducible infeasible subset (IIS, Gurobi \texttt{computeIIS}) of the copy and record the names of at most $50$ of its linear rows and general constraints.
\end{enumerate}
The original model is not changed; a failed completion does not stop the solve.

\subsection{Relaxation Start}
\label{sec:warm_relaxation}

If the run option \texttt{relaxation\_warm\_start} (Section~\ref{sec:run_options}) is true and no start or hint was applied (\texttt{applied} is false in the report \texttt{warm\_start}):
\begin{enumerate}[nosep,label=\arabic*.]
  \item Copy the model and relax its linear rows with Gurobi's \texttt{feasRelaxS} (sum of absolute violations); integrality, variable bounds and general constraints are kept.
  \item Optimise the copy with the time limit $\max\{1,\ \texttt{relaxation\_time\_limit}\}$ seconds and the MIP gap $0.05$.
  \item If the copy has a solution, set \texttt{Start} of every integer variable of the original model to the rounded value of the variable of the same name in the copy.
\end{enumerate}
The relaxed solution is not a point of the original model.

\subsection{Warm Starts in Sweeps}
\label{sec:warm_sweeps}

With \texttt{warm\_start=True}, the source of a case is the result of the nearest preceding case of the same $H_1$ that has a solution, used in the mode \texttt{warm\_start\_mode}. The first case of each $H_1$ has no source; a case with an error or without a solution is never a source.

\subsection{Greedy Heuristic}
\label{sec:greedy}

\begin{lstlisting}[language=Python]
build_greedy_warm_start(cfg, *, repair_trigger=0.70)
    -> (dict, GreedyWarmStartReport)
\end{lstlisting}
Module \texttt{fleet\_management.greedy\_warm\_start}, not exported; it works for every model. \texttt{cfg} is the normalised configuration (\texttt{load\_config}, Section~\ref{sec:data_flow}); $r = \texttt{repair\_trigger}$ must lie in $[0,1]$ (\texttt{ValueError}).
The returned source has the keys \texttt{H1}, \texttt{H2}, \texttt{x}, \texttt{m}, \texttt{r}, \texttt{complete\_binary\_start} (\texttt{true}) and \texttt{completion\_time\_limit} ($60$).

\emph{Construction pass.} A proxy state $\hat s_{i\ell}$ starts at $\mu_{0,i\ell}$. For each day $k = 1,\ldots,T$:
\begin{enumerate}[nosep,label=\arabic*.]
  \item Order the missions by decreasing $\max_{i,\ell} \mu^{\inc}_{i\ell jk}/\tau_{i\ell}$; a tie goes to the larger $j$.
  \item In this order, give each mission to the train $i$ without a mission on day $k$ that minimises, in lexicographic order,
    $\bigl(\max_\ell (\hat s_{i\ell} + \mu^{\inc}_{i\ell jk})/\tau_{i\ell},\ \sum_\ell (\hat s_{i\ell} + \mu^{\inc}_{i\ell jk})/\tau_{i\ell}\bigr)$; a tie goes to the smaller $i$.
    Add $\mu^{\inc}_{i\ell jk}$ to $\hat s_{i\ell}$. The check $F > M$ (Section~\ref{sec:consistency_checks}) guarantees a train for every mission.
  \item A train without a mission is idle, unless some component has $\hat s_{i\ell} > r\,\tau_{i\ell}$: then $x_{i0k} = 1$, and every such component is repaired ($x^m_{i\ell k} = 1$, $\hat s_{i\ell} \leftarrow (1-\rho_{i\ell})\,\hat s_{i\ell}$ for every repair law).
\end{enumerate}
The construction pass schedules no replacement.

\emph{Loop pass.} For each cell, compute the reference trajectory $\zeta$ (Section~\ref{sec:encoding}) of the current schedule from the initial values, starting anchors and replacement values of the inputs. The excess $e$ of the cell is the largest of the loop excesses $\max\{0,\ \zeta^{q}_{T} - \zeta^{q}_{H_1}\}/M_q$ of every tracked quantity and anchor $q$ with natural range $M_q$ (Section~\ref{sec:loop}), and of the violations of the reliability row on every day, divided by the natural range of the bounded quantity. The row is taken in the form built at the cell (Sections~\ref{sec:dyn_gaussian}--\ref{sec:dyn_rainflow}): the exact row for \texttt{"exact"}, the tangent row for \texttt{"tangent"}, and for \texttt{"pwl"} the cap of the segment that contains the mean of the day (Section~\ref{sec:linear_forms}).
While $e > 10^{-10}$: for every free day $k \in \{H_1+1,\ldots,T\}$ (the train has no mission, the cell no intervention), put a repair of the cell on day $k$ (the train goes to the depot) and recompute $e$; keep the repair with the smallest $e$, a tie to the later day.
If no repair lowers $e$ by more than $10^{-10}$ and replacement is allowed, repeat the trial with a replacement. If no trial lowers $e$, count one failure for the cell and go to the next cell. A start with failures is returned.

\emph{Report.} \texttt{GreedyWarmStartReport.as\_dict()} returns plain Python types. Keys: \texttt{repairs} and \texttt{replacements}, the numbers of ones in \texttt{m} and \texttt{r}; \texttt{repeatability\_feasible}, true without a failure; \texttt{repeatability\_failures}, the number of cells with a failure; \texttt{maximum\_repeatability\_excess}, the largest raw excess over all cells after the loop pass; \texttt{maximum\_proxy\_ratio}, the largest $\hat s_{i\ell}/\tau_{i\ell}$ of the construction pass and reference mean over $\tau_{i\ell}$ of the loop pass; \texttt{assignment\_order}, for each day, the missions in the order treated.

\section{Validation Tools}
\label{sec:validation}
% ================================================================

The tools check a saved result against its input; they do not call the optimiser. Each tool reads the input with the input reader and \texttt{load\_config} (Section~\ref{sec:data_flow}), reads a result file in any format that \texttt{solve()} writes, and takes the model of each cell from the result key \texttt{model}.

\subsection{Structural Validator}
\label{sec:validation_structural}

\begin{lstlisting}[language=Python]
validate(input_path, results_path, validation_path="validation.yaml",
         tol=1e-6) -> dict
\end{lstlisting}
The report is written to \texttt{validation\_path} (\texttt{.yaml}, \texttt{.yml} or \texttt{.json}; no extension gets \texttt{.yaml}; the folder is created) and returned.
Errors: \texttt{FileNotFoundError} for a missing file; \texttt{PermissionError} for a folder that is not writable; \texttt{ValueError} for an unsupported extension, a result without \texttt{x} (missing or \texttt{null}), an input that fails Section~\ref{sec:consistency_checks}, or sizes $F$, $M$, $L$, $H_1$, $H_2$ or array shapes that differ between result and input (named in the message).
The status is not a check: a feasible incumbent is validated like an optimal solution, and the report echoes the status. A check passes if its violation is at most \texttt{tol}. The checks, each with its violation:
\begin{itemize}[nosep]
  \item \texttt{binary}: $x$, $x^m$, $x^r$ take only the values $0$ and $1$; the largest distance of an entry from $\{0,1\}$.
  \item \texttt{one\_activity}: $\sum_{j=0}^{M} x_{ijk} \leq 1$ (Section~\ref{sec:assignment}); $\max\{0,\ \max_{i,k}(\sum_j x_{ijk} - 1)\}$.
  \item \texttt{mission\_coverage}: every mission $j = 1,\ldots,M$ has $\sum_{i} x_{ijk} = 1$ (the depot $j = 0$ is not summed); $\max_{j \geq 1,k} |\sum_i x_{ijk} - 1|$.
  \item \texttt{depot\_gating}: $x^m_{i\ell k} + x^r_{i\ell k} \leq x_{i0k}$ (Section~\ref{sec:depot}), and $x^r = 0$ if \texttt{allow\_replacement} is false; the largest excess of the left side over the right side.
  \item \texttt{idle}, if the result has the key \texttt{idle} (Section~\ref{sec:output}): $\max |\texttt{idle}_{i\ell k} - (x_{i0k} - x^m_{i\ell k} - x^r_{i\ell k})|$.
  \item \texttt{loop\_}$q$ for $q \in \{\texttt{mu}, \texttt{v}, \texttt{R}, \texttt{K}, \texttt{g\_mu}, \texttt{g\_v}, \texttt{g\_R}, \texttt{g\_K}\}$: the loop row $q_{i\ell T} \leq q_{i\ell H_1}$ (Section~\ref{sec:loop}), with \texttt{NaN} and \texttt{null} entries skipped; $\max\{0,\ \max_{i,\ell}(q_{i\ell T} - q_{i\ell H_1})\}$.
  \item \texttt{objective}: the saved objective $o$ is not below the recomputed objective $r$; $\max\{0,\ r - o\}/\max\{1, |o|\}$. The recomputed objective is Eq.~\eqref{eq:a_objective} in the objective mode of the input, with the day cost of Eq.~\eqref{eq:a_daycost} on the saved $x$, $z$ ($0$ where \texttt{NaN}) and $x^r$, the costs of the input, and the saved $u$.
\end{itemize}

\emph{Keys:} \texttt{status}, \texttt{solver\_objective}, \texttt{recomputed\_objective}, \texttt{tolerance}; \texttt{checks}, a list of records with \texttt{name}, \texttt{passed}, \texttt{violation} and \texttt{tolerance}; \texttt{passed}, true if all checks passed; \texttt{max\_violation}.

\subsection{Validators of the Gamma Model}
\label{sec:validation_gamma}

Each validator takes the normalised configuration \texttt{cfg} (\texttt{load\_config}) and the result dictionary, and returns a report of plain Python types. Its file version takes an input path, a result path and \texttt{report\_path} (default \texttt{None}); it writes the report as YAML or JSON (\texttt{ValueError} for another suffix) and creates the folder.
\texttt{ValueError} if \texttt{cfg} has no Gamma cell; if a required array is missing, has a wrong shape or a non-finite entry; if an array that must be binary is not within \texttt{tolerance} of $\{0,1\}$. \texttt{tolerance} (default $10^{-8}$) must be positive. With \texttt{raise\_on\_failure=True}, a report with \texttt{valid = false} raises \texttt{AssertionError}.

\emph{Replay validator.}
\begin{lstlisting}[language=Python]
validate_gamma_replay_schedule(cfg, result, *, tolerance=1e-8,
                               raise_on_failure=False) -> dict
validate_gamma_replay_files(input_path, result_path, report_path=None,
                            **kwargs) -> dict
\end{lstlisting}
It reads \texttt{x}, \texttt{m}, \texttt{r} (optional), \texttt{mu}, \texttt{z} and, for $\ARDone$ cells, \texttt{g\_mu}. Global violations (strings in \texttt{global\_violations}): a result horizon other than $T$; a train with more than one activity; a mission not covered exactly once; a repair and a replacement of a cell on one day; an intervention on a day with a mission or without a depot day.
For each Gamma cell and day $k$, the reference trajectory of $\mu$ and $g^{\mu}$ (Section~\ref{sec:encoding}) is computed from the saved schedule, with the initial value, starting anchor and replacement value of the cell. The event of the day is \texttt{"replacement"}, \texttt{"repair"}, \texttt{"mission"} or \texttt{"idle"}. The errors are:
\begin{itemize}[nosep]
  \item \texttt{tracked\_mean}: $\max\{0,\ \text{reference mean} - \texttt{mu}_{i\ell k}\}$; \texttt{mean\_anchor}: the same for \texttt{g\_mu}, under $\ARDone$;
  \item \texttt{removed\_mean}: $\max\{0,\ x^m_{i\ell k}\,\rho_{i\ell}(\mu_{i\ell,k-1} - g_{i\ell,k-1}) - z_{i\ell k}\}$, with $g = 0$ under $\ARDinf$ (Section~\ref{sec:repair_cost}); skipped where $z$ is \texttt{NaN} ($C_{R,i\ell} = 0$);
  \item \texttt{cap}: $\max\{0,\ \texttt{mu}_{i\ell k} - A_1(\beta^*\tau,\varepsilon)/\beta^*\}$ (Section~\ref{sec:dyn_gamma});
  \item \texttt{repeatability}: $\max\{0,\ \texttt{mu}_{i\ell T} - \texttt{mu}_{i\ell H_1}\}$, and the same for the saved anchor.
\end{itemize}
An error above \texttt{tolerance} adds a record \texttt{i}, \texttt{l}, \texttt{k}, \texttt{event}, \texttt{field}, \texttt{expected}, \texttt{saved}, \texttt{error} to \texttt{violations}.
\emph{Keys:} \texttt{validator}; \texttt{valid}, true without a global violation and without a violation; \texttt{solver\_status}, \texttt{dimensions}, \texttt{gamma\_cells}, \texttt{gamma\_ard1\_cells}, \texttt{transitions\_checked}, \texttt{repairs}, \texttt{replacements}; \texttt{maximum\_errors}, the largest error of each field; \texttt{global\_violations}, \texttt{violations}, \texttt{timing}.

\emph{Exact validator} (module \texttt{gamma\_utils.gamma\_tail\_validator}, not exported).
\begin{lstlisting}[language=Python]
validate_gamma_tail_bound_schedule(cfg, result, *, tolerance=1e-8,
    convolution_tolerance=1e-12, max_series_terms=100000,
    include_steps=False, raise_on_failure=False) -> dict
validate_gamma_tail_bound_files(input_path, result_path, report_path=None,
                                **kwargs) -> dict
\end{lstlisting}
For each Gamma cell and day $k = 1,\ldots,T$, the true damage is a list of independent Gamma terms (Section~\ref{sec:dyn_gamma}). A mission adds a term with the exact rate of its increment. A repair multiplies the rate of the repairable terms by $1/(1-\rho)$, and removes them for $\rho = 1$; under $\ARDone$ the repaired terms join the frozen part of the anchor. A replacement starts a new list with the replacement term.
An initial or replacement damage without a rate (\texttt{gamma\_beta\_0} or \texttt{gamma\_beta\_new} omitted) is a known constant $c$, not a term: the tail is $\Pr(\text{sum of the terms} > \tau - c)$, and $1$ if $c > \tau$.
The tail $\Pr(D_k > \tau)$ is computed by the Moschopoulos series (with equal rates, the Gamma tail); the upper bound is the partial sum plus the remaining mixture mass, which is at most \texttt{convolution\_tolerance}. \texttt{RuntimeError} if the series does not reach this tolerance within \texttt{max\_series\_terms} terms. \texttt{convolution\_tolerance} must lie in $(0,1)$; \texttt{max\_series\_terms} must be positive.
A day passes if the upper bound is at most $\varepsilon_{i\ell} + \texttt{tolerance}$, the saved mean is at least $\mathbb{E}D_k - \texttt{tolerance}$ and, under $\ARDone$, the saved anchor is at least the exact mean of the frozen part minus \texttt{tolerance}.
\emph{Keys:} those of the replay report; \texttt{minimum\_reliability\_slack}, the minimum of $\varepsilon$ minus the upper bound; \texttt{worst\_reliability}, the step that attains it; \texttt{maximum\_remaining\_mass}; the numbers of series terms and the timing of the tail computations; with \texttt{include\_steps=True}, the list \texttt{steps} (terms and values of every cell and day).

\emph{Monte Carlo validator.}
\begin{lstlisting}[language=Python]
validate_gamma_stochastic_schedule(cfg, result, *, repetitions=100000,
    random_seed=20260908, maximum_schedule_failure_rate=None,
    confidence_level=0.95, batch_size=20000, tolerance=1e-8,
    raise_on_failure=False) -> dict
validate_gamma_schedule(cfg, result, *, mode=None, repetitions=None,
    random_seed=None, maximum_schedule_failure_rate=None,
    confidence_level=None, batch_size=None, tolerance=1e-8,
    raise_on_failure=False) -> dict
validate_gamma_schedule_files(input_path, result_path, report_path=None,
                              **kwargs) -> dict
\end{lstlisting}
The schedule is fixed, and only Gamma cells are sampled. In each of \texttt{repetitions} runs, the true damage of every Gamma cell is drawn: the initial damage, each mission increment and each replacement draw are independent Gamma variables with the means and rates of the inputs. Under $\ARDone$ the initial damage is the sum of two independent terms with means $g^{\mu}_0$ (the anchor) and $\mu_0 - g^{\mu}_0$; a damage without a rate is the constant of its mean.
Each day the repair law acts on the sampled path: $D \leftarrow (1-\rho)\,D$ under $\ARDinf$; $D \leftarrow g + (1-\rho)(D - g)$, then $g \leftarrow D$, under $\ARDone$. A replacement draws the damage of the replacement part and, under $\ARDone$, sets $g$ to it. After each day the run records whether $D > \tau$. A \emph{schedule failure} is a run in which some Gamma cell exceeds its threshold on some day.
The generator is seeded with \texttt{random\_seed}, and draws are made in batches of \texttt{batch\_size} runs; the same arguments give the same report. \texttt{confidence\_level} must lie in $(0,1)$; \texttt{repetitions} and \texttt{batch\_size} must be positive; \texttt{maximum\_schedule\_failure\_rate}, if given, must lie in $[0,1]$.
Each failure rate (of the fleet, of a cell, of the worst day of a cell) comes with its one-sided Clopper--Pearson upper bound at \texttt{confidence\_level}: for $f$ failures in $n$ runs, the \texttt{confidence\_level}-quantile of the law Beta$(f+1,\ n-f)$, and $1$ if $f = n$.
\texttt{valid} is true if no target is given, or if the observed schedule failure rate is at most \texttt{maximum\_schedule\_failure\_rate}.
\emph{Keys:} \texttt{validator}, \texttt{mode}, \texttt{valid}, \texttt{timing}, the arguments used; \texttt{scope} (``Gamma cells only''); \texttt{complete\_fleet\_validation} (false if the fleet has other cells); \texttt{excluded\_cells} (\texttt{i}, \texttt{l}, \texttt{component}, \texttt{model}, \texttt{reason} of each other cell); \texttt{schedule} (\texttt{failed\_replays}, \texttt{failure\_rate}, \texttt{failure\_rate\_upper\_confidence\_bound}, \texttt{maximum\_failure\_rate}, \texttt{observed\_target\_met}, \texttt{confidence\_qualified\_target\_met}); \texttt{cells}, for each Gamma cell \texttt{i}, \texttt{l}, \texttt{component}, \texttt{repair\_model}, \texttt{threshold}, \texttt{analytical\_epsilon}, \texttt{failed\_replays}, \texttt{failure\_rate} with its bound, \texttt{worst\_time\_step} with its failures, rate and bound, \texttt{maximum\_sampled\_damage}, \texttt{maximum\_threshold\_excess}.

\texttt{validate\_gamma\_schedule} runs the validators that \texttt{mode} selects: \texttt{"deterministic"} (replay), \texttt{"stochastic"} (Monte Carlo) or \texttt{"both"}, with the keys \texttt{deterministic} and \texttt{stochastic} and \texttt{valid} true if both are valid; another value raises \texttt{ValueError}. An argument that is \texttt{None} takes the value of the key of the same name in the input block \texttt{validation} (Section~\ref{sec:run_options}), otherwise its default; the default of \texttt{mode} is \texttt{"deterministic"}.
